# 电音档案 / Electronic Music Field Notes

一个以「制作课 + 知识库」为双核心的电子音乐学习站。制作课按真实做歌流程推进，知识库负责查原理、找关系、回源头；两者共用同一套知识源与合成音频示例。

- **制作课**：8 个阶段、22 节短课，从工程模板做到导出成曲。每课有产出、完成标准、前置课与相关知识库链接。
- **知识库**：1376 个条目、158 个知识文档、1541 个检索分块；支持全库检索、风格图谱、大族/条目/文档详情。
- **听感层**：60 条高频风格的「一句人话 + 三个听点 + 8 秒试听」，4 × 4 速度×律动矩阵，1080 × 1440 分享卡；没有专属文案的 1316 条走同族回退，全部有声音。
- **DJ 工具**：两首歌能不能接（BPM / 律动 / 低频三条规则）、BPM 邻接表、现场判定；离线速查卡断网可用。
- **工作室**：六个可动手模块（节拍、和弦、低音、旋律、音色、结构），共用一个 4 小节循环，边播边改。
- **课程内动手**：每节课的「动手」区块可就地展开对应工作室模块，不跳页、不打断阅读。
- **练习 / 实验室**：风格听辨、BPM 估速、七组音色实时开关。
- **声音**：所有试听由 Web Audio 实时合成，不使用原曲录音。

完整的模块划分、页面结构、课程模型与关联方式见 [docs/information-architecture.md](docs/information-architecture.md)。第一次使用建议先读 **[docs/user-guide.md](docs/user-guide.md)（阅读与使用指南）**：三种打开方式、网页操作手册、知识库阅读方法、Agent 接入与 FAQ。

## 视觉与交互语言

视觉方向是 **Club Rig / Soundsystem**：把页面当成一套扩声系统与一张 Rave 传单，而不是通用的「深色卡片网格」。

- **色彩是信号，不是装饰**：焦油黑 `#060607` 打底；钠灯琥珀 `#ffb000` 只表示「当前位置 / 主操作 / 已完成」；激光洋红 `#ff2e63` 只表示「下一课 / 正在播放 / 需要修正」；信号冰蓝 `#2fd8ff` 只表示「参考信息 / 独奏」。大族的四个色相按音域从低到高排列（暖→冷），并且只出现在 2px 边线、圆点与电平帽上，不再铺满整块表面。
- **字体与阅读尺度**：Bahnschrift 窄体承担展示标题与大号阶段编号；正文使用系统无衬线，**17px / 行高 1.86**，段落宽度限制在 62–66 字符；Cascadia Mono 承担 BPM、阶段、时间码与快捷键。数据一律使用等宽数字（`tabular-nums`）。标题分四级：页头 h1（约 2.7rem）→ 章节 h2（约 2.2rem，带编号）→ 区块标签（14px）→ 正文（17px），每一级在字号与字重上都不重叠。
- **章节边界**：每个章节以「编号 + 琥珀短线 + 标题」开头，区块之间用 1px 实线加 56–88px 留白分隔；课时页把内容切成 `01 概念 → 02 先听 → 03 动手 → 04 自检 → 05 回查` 五个带编号的块，读到哪里一目了然。
- **结构语法**：一小节 = 16 格。页头下方是一条 16 分格的 **transport 标尺**，播放时激光色播放头随音频推进；课程进度是一条 22 格、按 8 阶段分组的步进尺，每格可直接点击跳课；课时的完成状态、练习的对错、实验室的七层开关都复用同一套「格 / 通道」语义。
- **图标**：取自硬件而非通用线性图标集 —— 步进序列、黑胶、信号图、波形、推子组。
- **动效**：只保留与声音有关的运动。页头 12 段电平表读取主总线真实 FFT 数据（`AnalyserNode`），静音时归零；播放头、鼓机播放头与指示灯都按当前 BPM 换算节拍长度。页面切换、悬停与筛选使用 step 曲线（`cubic-bezier(1,0,0,1)`）而不是缓动，读起来像切片而不像呼吸。
- **操作反馈**：标记完成前先勾选自检清单，按钮上实时显示「自检 2/3」；完成后写入进度、更新页头胶囊并弹出带「下一课」的提示。课时页底部固定操作条让上一课、完成、下一课始终可达。

## 工作室：九个模块怎么串成一条线

参考 Learning Music 的教学结构：一个概念一屏、循环一直在响、每次操作都能立刻听到结果。但配色、字体与步进网格沿用本站的 Club Rig 系统，不做成另一个站点。

九个模块按**制作顺序**编号，与课程的八个阶段同序（阶段 04「旋律与音色设计」拆成旋律和音色两块，因为一个是音高序列、一个是频谱调参）。划分依据、边界规则与完整方案见 [`docs/hands-on-modules-plan.md`](docs/hands-on-modules-plan.md)。

| 模块 | 你做的操作 | 实时反馈 | 与其它模块的关系 |
| --- | --- | --- | --- |
| 01 信号链 | 五条轨道各认一个声部（点击即试听）；四个效果器拖动手柄或用 ↑↓ 换位；A/B 两套顺序一键对比 | 点轨道头听到该轨真实音色（同样经过效果器链）；重排后信号流图扫过一遍；播放中改顺序不中断 | 定下声音的拓扑，其余模块的素材都要流经这条链 |
| 02 节拍 | 点格子开/关 Kick、Clap、Hat、Open Hat；4 套预设；拖动涂抹 | 每次点亮立即试听该音色；播放头逐格扫过；读数显示各层音符数 | 鼓是底层，后面所有模块都在它上面叠 |
| 03 低音 | 3 行（根音 / 五度 / 八度）×16 格；3 组音型 | 点击试听对应音高；上方标出四小节和弦 | 同一音型在四小节里自动换根音，跟着 04 走 |
| 04 和弦 | 4 个小节各选 1 个和弦；3 组进行预设；单小节试听 | 选中即时发声；显示级数（i / VI / III / VII）与一句情绪描述 | 低音的根音由这里的和弦决定 |
| 05 旋律 | 8 个音阶音 ×16 格；3 组动机 | 点击即试听；只在调内，不会跑调 | 音阶由项目调性决定，和 03/04 同调 |
| 06 音色 | 6 个推子（滤波、共振、失真、延迟、混响、Bass 滤波）+ 3 个音色选择 | 播放中拖动，下一拍生效 | 效果在总线上，同时改变鼓、和弦、旋律 |
| 07 结构 | 6 个段落 ×（类型 + 小节数）；增删段落 | 播放时按段落逐层加减，当前段高亮 | 复用 02–05 的内容，只控制"什么时候出现" |
| 08 混音 | 七层通道条：电平 / EQ / 声像 / 发送（**搭建中**） | 面板说明规划中的频段占用图与电平表 | 改层与层的相对关系，不动总线整体性格 |
| 09 导出 | 项目模板 + 离线渲染下载 WAV（**搭建中**） | 面板说明渲染流程与复盘表单 | 只读全部数据，不改任何模块的内容 |

> 标「搭建中」的三块先给出诚实的占位面板：说明建成后能做什么、会承接哪些课时任务，并链到对应课程。不放假推子 —— 一个拉不动的推子会教错"推子是什么"。音频、状态与切换机制本身已经全部可用。

### 模块之间怎么切换

四个入口，都**不中断音频、不重置播放头**：

| 入口 | 位置 | 说明 |
| --- | --- | --- |
| 模块标签栏 | 顶部 | 主入口。≥1181px 九列一行，640–1180px 五列两行，窄屏三列三行（英文副标题隐藏） |
| 键盘 `1`–`9` | 全局 | 熟手用。`空格`仍是播放 / 停止 |
| 上一块 / 下一块 | 走带区 | 按制作顺序线性推进，到头即停（不回绕——编号是制作顺序，回绕会读成循环） |
| 课时页「在这里动手」 | 课时内 | 内嵌展开单个模块，走带区的上一块 / 下一块同样可用 |

九个模块**共用同一个 4 小节循环与同一条总线**，所以切模块换的是控制面板，不是声音。这就是"改完鼓、切到低音、边听边写"能成立的原因。

### 音频实现要点

- **一个会话读活数据**：`EMAudio.startStudio({ read })` 每 16 分音符调用一次 `read()`。所有编辑写进同一个 `project` 对象，回调下一次取值就能听到，不用重启播放。切模块也不打断循环。
- **相对音高而不是绝对音高**：低音行存的是和弦音的偏移（0 / 7 / 12），旋律行存的是音阶级数。换和弦时低音自动换根音、旋律自动留在调内 —— 这是模块之间真正的数据衔接，不是视觉联动。
- **效果器分两段，职责不同**：会话输出先进**可重排的插入链**（失真 / EQ / 压缩 / 混响四个节点），再进**总线音色**（失真 → 低通滤波 → 主输出，带一条带反馈的延迟旁挂）。插入链归信号链模块管，只改**顺序**；总线音色归音色模块管，只改**参数**。两个模块各改各的，不会互相打架。`updateStudio()` 用 `setTargetAtTime` 平滑改参数，避免拉推子时爆音。
- **重排只重新接线，不改参数**：`wireStudioChain()` 断开链段内的连接再按新顺序连回去。已经排程的 voice 保持旧路径直到结束，之后的走新路径——所以播放中拖动也能听到变化，不用停。四个插入的参数是固定的：如果重排时参数也跟着变，A/B 比较的就变成「两种声音」而不是「两种顺序」，这一课就不成立了。
- **四个插入各有实际作用**，不是占位：失真带 −6dB 补偿（否则「失真在前」永远只是更响，会教错东西）、EQ 做中频挖坑 + 存在感提升、压缩带 +3.2dB makeup、混响是串行 wet/dry 而不是发送（发送的话它放在哪一位都差不多，正是这一课要否定的）。
- **试听也走插入链**：`previewStudio()` 与新增的 `auditionTrack()` 都把信号送进 `chainInput`，所以「点轨道头试听」听到的是当前顺序下的声音，不是一条旁路的干声。
- **调度与视觉分离**：音频用 25ms 轮询提前 120ms 排程（避免 setTimeout 抖动），画面用 `getStudioPlayhead()` 按 `ctx.currentTime` 反算当前格，再用 `requestAnimationFrame` 上色。视觉晚于声音，但永远不会和声音不同步。
- **总线路由**：每条 voice 内部已连接到 `session.gain`；工作室把它断开后串进自己的效果链，因此鼓、Bass、和弦、旋律共享同一套滤波与空间。
- **试听不打断循环**：点格子、点和弦走 `previewStudio()`，不新建会话，所以循环继续跑。
- **结构门控是纯函数**：`gateForBar(project, bar)` 只吃「工程 + 小节号」，吐出门控后的工程副本，不碰 DOM、不碰时钟。会话每个 16 分音符把**自己算出的绝对小节号** `absBar` 传进来，所以段落切换跟着音频时钟走，不受 UI 帧率影响。
  - 会话循环只有 4 小节，`head.bar` 每 4 小节归零，所以编排需要另一个持续递增的坐标。`absBar` 由 `elapsed / stepDuration` 直接算出，**不能用调度器的 `loops` 计数器**：调度有 120ms 前瞻，`loops` 会在播放头真正越过循环点之前就递增，两者相加会让 `absBar` 在每个循环边界跳高再回落（这个 bug 真的出现过，被验证脚本抓到）。
  - 高亮和发声共用同一个 `blockIndexAt()`，所以灯和声音不可能不一致。

### 数据与进度

状态分三层，生命周期各不同：

| 层 | 内容 | 存在哪 |
| --- | --- | --- |
| **L1 工程** | BPM、swing、和弦、四轨图案、音色参数、结构、上次所在模块 | `localStorage: em-studio-v1` |
| **L2 视图** | 每个模块的滚动位置 | `localStorage: em-studio-ui-v1` |
| **L3 会话** | 播放 / 停止、播放头 | 不持久化 |

L3 刻意不存：刷新后自动播放会被浏览器的自动播放策略拦掉，所以重新打开时正确地停在「停止」。

L2 是后加的。之前切模块会丢位置——在结构模块滚到底部调完段落，切回节拍再切回来，滚动条回到顶部。现在每个模块各自记住自己的滚动位置。

- **完成度按"你动过"计算**：点过格子 / 选过和弦 / 拉过推子 / 改过结构才点亮该模块。示范工程本身是完整的，所以不能按"内容是否齐全"判断，否则一进页面就 5/6。
- **模块数从 6 增到 9 不需要迁移代码**：`completion()` 遍历 `MODULES` 数组生成状态，进度环的分母自动从 `/6` 变成 `/9`，旧用户已勾选的模块保持勾选。原有六个模块的 id 一个没改，所以旧的 `module` 与 `done{}` 继续有效。
- 每个模块都指向对应制作课（如 03 低音 → `kick-and-bass`），学完可以回到课程页看完整解释。
- 「上一块 / 下一块」就地切换并保持播放，不会因为跳转而中断你正在听的循环。

### 切换协议

`switchModule()` 的步骤顺序是有讲究的，五步都不能换位：

1. **先落盘旧模块的视图状态** —— 必须在改 `project.module` 之前，否则滚动位置会被记到新模块名下。
2. 记录新的模块 id。
3. 重渲染面板 —— **这一步不碰音频**。
4. 恢复新模块的滚动位置（等两帧，等布局稳定后再设 `scrollTop`，否则会被钳到 0）。
5. 补画播放头 —— 播放中切模块时，新面板刚建出来所有格子都是暗的，不补这一下会闪一帧空网格。

内嵌模式（课时页）另外要同步底部「打开完整工作室」链接的 `?m=` 参数——`renderPanel()` 只重建面板内部，那个链接在外层，不同步会一直指向首次打开时的模块。

### 键盘与触摸

- 空格：播放 / 停止；数字 `1`–`9`：切换模块。
- 格子在手机上改为横向滚动、行头钉住，单格最小约 28×38px；桌面端单格约 75×52px。

## 制作课与工作室怎么连起来

课程页原本的「动手」是一段文字：读完就结束了。现在它是一扇门。

### 衔接方式

`app.js` 里有一张 `LESSON_STUDIO` 映射表，把 22 节课逐一指向它真正要练的那个模块：

| 课时 | 模块 | 建议动作 |
| --- | --- | --- |
| daw-and-tracks | 01 信号链 | 给五类轨道各认一个声部 |
| signal-chain-basics | 01 信号链 | 看清 MIDI → 总线四步 |
| drum-programming / groove-and-half-time / drum-processing | 02 节拍 | 搭鼓型、拉 Swing、听层次 |
| kick-and-bass / bass-sound-design / low-end-control | 03 低音 | 让位、换性格、留根音行 |
| chord-progressions / chord-texture | 04 和弦 | 选进行、切音色 |
| lead-hook | 05 旋律 | 两三个音写动机，重复它 |
| synth-controls / sampling-chops | 06 音色 | 一次只拉一个推子；切片当乐器排 |
| structure-eight / transitions / automation-energy | 07 结构 | 分配小节数，听层数加减 |
| gain-stage / eq-space / space-stereo | 08 混音 | 留余量、让频段、做空间 |
| project-house / project-bass / finish-export | 09 导出 | 套模板、渲染、下载 WAV |

跳转链接带两个参数：`#/studio?m=bass&from=kick-and-bass`。`m` 指定模块，`from` 带上课时 id。

工作室读到 `from` 后会渲染一条来源条（课时名 + 阶段 + 「回到这一课」），课时标题由 `app.js` 解析后通过挂载参数传入——`studio.js` 不直接依赖课程数据，保持单向依赖。

### 就地展开，而不是跳页

最早的做法是把「动手」做成跳转链接，结果是「读一句 → 跳走 → 试一下 → 跳回来」的来回折腾。现在改为**在课时页内展开**：

- 默认收起，点「在这里动手」才挂载 —— 课时页保持轻量。
- 内嵌模式只渲染**走带 + 单个模块 + 状态条**，不渲染页头和模块标签（课时页已经提供了标题与上下文）。
- 内嵌模式下走带区的「上一块 / 下一块」仍然可用，所以可以在课时页里顺着往下走，不必先跳出去。
- 底部保留「打开完整工作室」出口，想按顺序做完九块时再去。
- 收起时卸载并停掉音频，不留后台循环。

`EMStudio.mount(node, kit, options)` 的 `options.embedded` 控制这个分支，`options.module` 指定挂哪一块。完整工作室的挂载路径完全没变。

### 两个播放器的冲突

课时页自带播放器（分层实验室、鼓组步进器等），内嵌工作室也是播放器 —— 而音频引擎**同一时刻只有一个会话**。实测过三种表现：

1. 课时播放器在响时打开工作室 → 工作室起来后，课时按钮还写着「停止」，但它已经不是发声的那个。
2. 工作室在响时点课时播放器 → 工作室按钮继续显示「停止」，实际声音已换人。
3. 收起工作室 → 课时播放器仍在跑。

修法是在两端各加一道：

- **打开工作室时**：若课时播放器在响，先 `Audio.stop()`。
- **课时播放器启动时**：`updateAudioUI` 里检测会话归属，若被非 studio 的播放器抢走，调用 `EMStudio.releaseSession()` 让工作室复位（模块内容与编辑保留，只重置走带）。
- 工作室自己的 `tick()` 也加了兜底：发现播放头消失就自我复位，避免 UI 谎报状态。

### 为什么用 `from` 而不是浏览器返回

用户可能是从搜索结果、直接输入地址、或从另一节课进来的。来源条回答的是「我在哪、怎么回去」，不依赖浏览历史，刷新后依然成立。

## 课程播放器的动态循环提示

课时页的四个播放器（节拍器、鼓组步进器、分层实验室、结构播放器）原本只有按钮文字变化。现在都跟着音频时钟走：

- **节拍器**：四个拍点逐拍点亮，读数显示「第 N / 2 小节」。
- **鼓组步进器**：一条竖列扫过 8 格（三行同时高亮，因为它们是同一时刻发声的），下方循环条显示进度。
- **分层实验室**：正在发声的层持续描边发光；关掉的层不亮。
- **结构播放器**：八个段落逐个激活，段内有一条扫描线在两小节里推进，顶部总进度条同步。

### 实现要点

统一走 `EMAudio.getPlayhead(demoId)`，它从 `ctx.currentTime` 反算位置，和工作室用的是同一个函数。三条规则：

1. **视觉只是读数**：播放头读音频时钟，不用 `setInterval` 自己数拍。画面可以晚一帧，但永远不会和声音错位。
2. **一个数据源**：结构播放器的「活动段」「扫描线」「总进度」原本分别来自 `state.section` 和播放头，会互相漂移；现在全部由播放头推导（段 = `floor(bar / 2)`）。
3. **停止时必须重绘**：`paintLessonPlayheads()` 不只挂在 rAF 循环里，也挂在状态变化上——否则停止后 rAF 循环结束，最后一格会永久亮着。

顺带修掉一个真实缺陷：会话的 `startTime` 领先约 0.1 秒，启动瞬间 `elapsed` 为负，取模后被折回接近末尾，所有读数会先闪一下 100%。已钳制到 0。

## 布局与响应式

- **铺满而不是居中留边**：`.site-shell` 不再设固定最大宽度，改为 `width: 100%` + `padding-inline: var(--shell-pad)`（`clamp(16px, 2.6vw, 72px)`）。1920px 视口下内容占 94.4% 宽度，2560px 下 94.7%，两侧只余设计留白，不再出现成片黑带。长文仍通过 `62–72ch` 的测量上限保持易读。
- **通栏条带**：页头、页脚用负 margin 抵消外壳内距，吸顶导航与 transport 标尺铺满整个视口，不会在屏幕中间出现接缝。
- **宽屏靠列数而不是拉宽卡片**：大族网格用 `--cols` 变量在 2/3/4/5/6 列之间切换（知识库页 4→6 列）。所有分栏用 `minmax(0, 1fr)`，避免内容把轨道撑破。
- **手机竖屏（320–430px）**：正文 17px、行高 1.86；微型等宽标签统一抬到 11–11.5px 下限；主按钮 46px 高、13px 字；页头图标按钮 40×40；步进格 34px 高；页脚与次级导航链接 36px 触控高度。课时底部操作条按 `env(safe-area-inset-bottom)` 让出 Home 指示条。
- **横向滚动条带**：课程路线、八段结构、大族卡片在窄屏改为横向滑动，带 `scroll-snap` 与「可左右滑动」文字提示，并隐藏滚动条。
- **没有横向溢出**：320 / 360 / 390 / 414 / 768 / 1024 / 1440 / 1920 / 2560 九个宽度 × 14 条路由逐项检测，页面级横向溢出为 0。三类曾经的溢出源已修：大族网格被 `.library-body` 的高特异性规则锁成 4 列（卡片仅 85px 宽）、`.module-card` 内 `<pre>` 的 `min-content` 撑破网格列、以及 About 页三列校正表格（现改为堆叠行）。

## 使用逻辑

页面按「一个目标一个入口」组织，避免同一件事出现两种做法：

- **学习路线可读成一条阶梯**：课程页顶部是 8 个阶段块，上方用三条难度带标出 `基础（00–02）→ 进阶（03–05）→ 完成（06–07）`；每个阶段块显示编号、短名、完成数与 22 格课时刻度，刻度可直接点击跳课。
- **每个阶段都写明三件事**：`进入`（需要先具备什么）、`知识点`（本阶段覆盖的概念，全部链到知识库）、`验收`（做到什么算过关）。当前 8 个阶段共 45 个知识点，全部指向真实条目或文档。
- **页头只有一处主操作**：每个内页顶部是紧凑页头（编号 / 标题 / 一句说明 / 关键数字 / 一个主按钮），不再每页重复「大标语 + 长解释」。
- **首页只保留一个 Hero**：鼓机试听与「开始 / 继续第一课」合并为一个动作；八阶段用紧凑 tracklist 呈现，不再与课程地图重复展开。
- **课程地图可直接跳课**：阶段块内的刻度每格对应一课；「只看未完成」会隐藏已完成阶段，减少滚动。
- **课时页只有一个任务链**：产出与交付物合并成一条 brief；五个编号区块固定「概念 → 先听 → 动手 → 自检 → 回查」；自检清单可勾选并驱动完成按钮。
- **练习与实验室支持键盘**：练习按 `1`–`4` 作答、`空格` 重听、`回车` 下一题；实验室按 `1`–`7` 开关图层、`S` 独奏。


项目现在有两种使用方式：

- **网页展示层**：`index.html`，适合人类阅读、学习与动手。
- **Agent 知识库模块**：`kb-module/`，可独立构建，提供 CLI、MCP stdio 与 HTTP API，详见 [kb-module/README.md](kb-module/README.md)。

## 学习逻辑

课程不是知识库的目录，而是一条制作路径。顺序按真实工作流而不是学科分类安排：

```text
工程与信号链 → 鼓组与律动 → 低频与 Bass → 和弦与情绪
→ 旋律与音色设计 → 编曲与能量 → 混音与空间 → 完成一首歌
```

每课的数据模型包含：

| 字段 | 作用 |
| --- | --- |
| `outcome` | 学完这一课能做到什么 |
| `deliverable` | 这一课要在 DAW 里留下的具体产物 |
| `prerequisites` | 前置课；缺少时课时页会提示先补哪一课 |
| `goals` | 课末自检清单 |

阶段层（`chapters[]`）另有四个字段，用来描述进阶关系：

| 字段 | 作用 |
| --- | --- |
| `tier` | 难度带：`基础` / `进阶` / `完成`，决定路线带的分组 |
| `entry` | 进入这一阶段前必须具备的能力 |
| `knowledge` | 本阶段知识点数组（`{ label, kb }`），`kb` 指向真实条目/文档 |
| `exit` | 阶段验收：做到什么算过关 |

课时内的其他字段：

| 字段 | 作用 |
| --- | --- |
| `concept` / `keyTerms` | 最小学理，够用就停 |
| `widget` | 站内可播放/可操作的示例，先建立听感 |
| `task` | 可以立刻在 DAW 或站内完成的动作 |
| `kbLinks` | 相关知识库条目/文档，用于回查原理 |
| `links` | 延伸阅读或工具入口 |

知识库在这里承担四件事：

1. **补原理**：课上的名词都能点回条目或文档，而不是停在口号。
2. **定顺序**：前置关系来自制作依赖（没有鼓组就不做低频让位，没有音色就不做混音），课时页会把缺失的前置课标出来。
3. **给验收**：每课的产出与自检清单让“学完了”变成“做出来了”。
4. **反向找课**：从知识库条目/文档或全库检索结果，都能看到“在课程中学习”。

## 双模块与关联方式

**制作课**（`data/course.js`）是编排层：每课声明产出、前置课、互动类型 `widget` 与相关知识库 `kbLinks`。**知识库**（`kb-module/dist` → `data/web.js`）是数据层，提供条目、文档、关系与检索。

- 课程 → 知识库：课时页把 `kbLinks` 渲染为条目/大族/文档链接；课时末尾还可继续全库检索。
- 知识库 → 课程：条目页和文档页显示“在课程中学习”；风格文档通过 `metadata.entryId`、大族文档通过 `metadata.familyId` 建立别名映射，所以 `g-1581` 也能找到关联到 `style:bigroom-house` 的制作课。
- 检索 → 课程：全库检索用 `searchLessons(query)` 同时匹配课时标题、概念、关键词与 `kbLinks` 标签，显示“相关课程”面板。
- 前置课 → 学习路径：课时页读取 `prerequisites`，把还没完成的先修课标出来并给出直达链接；不硬锁课，但顺序有明确依据。
- 练习/实验室 → 课程：练习结果建议回到相关课时；课程复用同一个 Web Audio 引擎与七组音色定义。

核心流程：

1. **第一次来**：首页 → 开始第一课 → 制作课地图 → 课时 → 播放示例 → 在 DAW 完成任务 → 对照交付物与自检清单 → 底部操作条标记完成 → 下一课。
2. **带着问题查**：知识库 → 搜索/图谱 → 条目/文档 → 在课程中学习 → 回到对应课时。
3. **卡住时补前置**：课时页前置课提示 → 回到先修课 → 完成后再继续。
4. **复习**：制作课地图进度 → 已完成课时 → 重听示例 / 重做任务；或搜索 → 相关课程。

## 声音与学习功能

- **首页单小节鼓机**：三行八步的 Kick / Clap / Hat，可直接改节奏并播放；播放头与音频同步，作为进入制作课的第一动作。
- **22 节制作课**：每课至少包含节拍器、8 步鼓机、对比试听、分层实验室、结构播放器或和弦试听中的一种，并配一个明确产出。
- **十种风格试听**：Bigroom House、Electro House、Deep House、Uplifting Trance、Techno、Trap、Future Bass、US Dubstep、Hardstyle、Future Rave。每个都是 2 小节循环，使用合成 Kick、Bass、和弦、Lead、FX 等搭出该风格的骨架。
- **音色实验室**：七组（打击乐 / 贝斯 / 和弦 / 人声 / 主奏 / 氛围 / 音效）可实时开关，BPM 可在 100–160 之间调整；适合先关掉所有层，再一层层加回来。
- **八段结构播放器**：16 小节、约 30 秒的结构示例，依次走过 Intro、Breakdown、Build-up、Drop、第二次间奏、第二次渐进、第二次 Drop、Outro，并高亮当前段落。
- **听辨练习**：风格四选一与 BPM 估速；带得分、连对与即时反馈。片段都是合成循环。
- **全局声音控制**：页头声音开关、底部播放条、进度条与音量；切换页面时播放状态保持，可随时停止。
- **不使用音频文件**：所有声音由 `audio.js` 通过 Web Audio API 实时合成，没有原曲录音，也没有版权音频下载。

首次播放需要用户点击（浏览器自动播放策略）。如果浏览器不支持 Web Audio，按钮会提示不可用，但文字、图谱与检索仍然正常工作。

## 重新生成数据

模块的自包含输入在 `kb-module/inputs/`：

- `taxonomy.md`：分类库 Markdown。
- `curated.json`：精编内容（含首页文案与入口）。
- `transcripts/`：转写资料。
- `source-map.json`：来源、作者、链接与许可说明。

修改输入后运行：

```bash
# 只构建 Agent 模块
node kb-module/bin/kb.mjs build

# 或：构建模块并同步网页数据
node scripts/build-data.mjs
```

`scripts/build-data.mjs` 会先生成 `kb-module/dist/`，再生成网页使用的 `data/kb.json`、`data/kb.js`、`data/curated.js`、`data/web.js` 与 `data/genres.csv`。网页不再单独维护解析逻辑。

课程内容 `data/course.js` 是手工编排的编辑层，不由模块生成；修改课时、任务、产出或 `kbLinks` 后刷新页面即可，不需要重新构建知识库。

解析规则：

- 按 Markdown 标题层级建立结构树；`前言` / `大纲` 不计入条目。
- 识别 `上位/下位`、`上/下`、`Related To`、`A.K.A./AKA`。
- 从正文提取 BPM、例曲、别名和结构下级。
- `待完善`、`交叉引用`、`待归档` 保留原始状态，不替原文补写。
- 条目的 `id` 基于原文行号，重新排版原文后链接可能变化。

## 已知限制

- BPM 只覆盖原文档明确写出数字的 181 个条目；没有数字不等于没有速度特征。
- 原文档有 90 个内容很少的条目，其中部分只是指向其他板块的交叉引用。
- 有 72 组同名或近名条目，分布在不同大族；详情页的面包屑与所属大族用于区分。
- 分类是有立场的民间整理，不是音乐产业的标准答案；同一声音在不同城市、厂牌、社群会有不同叫法。
- 例曲只提供文字索引，不提供音频；版权归原作者。请把本库当作学习与研究资料，不要当作音乐下载站。
- 试听片段是合成示例，不是原曲；它用于展示节奏、音色与结构差异，不能替代原曲欣赏。人声层用合成器模拟，不是真人录音。
- 音频依赖 Web Audio；老旧浏览器或禁用音频的浏览器只能使用文字与检索功能。
- 制作课不会替你操作 DAW：任务与交付物写在页面里，实际工程需要你在自己的软件里完成。
- 课程进度保存在浏览器 `localStorage`（键：`em-course-progress-v1`），没有账号或后端同步；换浏览器/清缓存会丢失。加载时会过滤已不存在的旧课时 ID。
- 课程是编辑内容，不自动从知识库生成；知识库更新后，若新增/改名了课程引用的条目或文档，需要同步检查 `data/course.js` 的 `kbLinks`。
- **听感层只覆盖 60 条**：其余 1316 条走「同族参考」，页面会明说「这不是这一条独有的声音」。`data/listen.js` 里如果写了不存在的 entryId，`check-listen.mjs` 会直接失败，不会静默空白。
- **BPM 大多数是编辑推断**：60 条里只有 6 条的区间来自原文明确的数字，其余是按大族与代表曲推的区间。卡片和面板都标了来源，推断值不要当唱片上的数字用。
- **分享卡没有二维码**：没有引入 qrcode 库，卡面印的是真实短链（`/music/s/<slug>/`）。要二维码的话，把库放进 `vendor/`，`share.js` 里的 `drawCode()` 换掉即可——现在这个位置是刻意留空的，不画扫不出来的假码。
- **识曲与 Set 曲线没做**：方案里评估过（`docs/listener-layer-plan.md` §6、§7.4），这两项需要真实录音验证与更多交互，没有进入本轮。
- **Service Worker 有版本号**：`sw.js` 的 `VERSION` 不变，老访客就会一直用旧缓存。每次改前端都要改它。本地开发时如果改完看不到变化，在 DevTools → Application → Service Workers 里点 Unregister 再刷新，或直接改 `VERSION`。

## 怎么验证

改动后跑一遍这三层，覆盖从「页面会不会撑破」到「线上真的能播」：

```bash
node scripts/serve.mjs                                  # 先起本地服务
./scripts/regression/run.sh                             # 全站回归（150 组合，约 5 分钟）
node scripts/regression/check-listen.mjs                # 听感层 + DJ 工具 + 离线（49 项）
node scripts/regression/check-p0.mjs                    # 结构门控（10 项）
node scripts/regression/check-p1.mjs                    # 九模块骨架（25 项）
node scripts/regression/check-p2.mjs                    # 信号链模块（35 项）
node scripts/regression/check-chain-layout.mjs          # 信号链面板布局：重叠/截断/越界（7 项）
node scripts/regression/check-embed-narrow.mjs          # 内嵌窄屏（2 项）
node scripts/regression/check-spectrum-codes.mjs        # 频谱代号（6 项）
node scripts/regression/check-live-deploy.mjs           # 部署后专项：本轮改动真的上线了吗（15 项）
node scripts/regression/live-check.mjs                  # 线上端到端（28 项）
node scripts/regression/live-mobile.mjs                 # 线上移动端（9 项）
```

`check-live-deploy.mjs` 与 `live-check.mjs` 的分工：后者验证「站点还能不能用」，前者验证「新东西上没上线」（信号条根数、补充桶分区、九模块标签这类具体特性）。每次部署后跑它，能避免「文件传了但页面还是旧的」这种静默失败。

跑子集做冒烟：`ROUTES_OVERRIDE="learn/kick-and-bass|library" WIDTHS_OVERRIDE="320 1920" ./scripts/regression/run.sh`

判定信号：`BAD` 横向溢出、`EMPTY` 内嵌工作室没挂载出内容（真实缺陷）、`NOOUT` 探针没回话（多半是服务没起，或**跑回归时文件正在被改动**）、`NOBTN` 该路由本来就没有动手模块（预期）。

探针会跳过「祖先里有真的在横向滚动的容器」的元素（`overflow-x: auto` 且 `scrollWidth > clientWidth`）。信号链 `.st-signal` 就属于这种：节点本来比窄屏宽，容器自带滚动，页面本身没溢出。这是判定规则，不是豁免——页面级 `docW > vw` 仍然照抓。

**跑之前先让文件停下。** 回归会 `--dump-dom` 抓探针输出，如果同时有别的进程在写 `app.js` / `data/kb.js`，浏览器可能加载到半旧半新的页面，结果是成片 `NOOUT` 而不是真实结论。同理，**回归结论是绑定数据版本的**：`data/kb.js` 的 `generatedAt` 一变，之前的「零溢出」就不再成立，必须重跑。

### 四条踩过的坑

**断言要区分「字段缺失」和「字段为空」。** 回归脚本曾报出 45 条 `EMPTY`，看着像大面积故障，实际是判定写成 `not d.get('content')` —— 探针在没有动手模块的路由下根本不输出 `content` 字段，`not None` 恒为真。45 恰好等于 9 个无模块路由 × 5 档宽度。现在探针会明确输出 `open:'nobtn'`。

**代号表要跟着大族一起长。** 知识库扩充到 29 个大族后，`FAMILY_CODES` 仍只有旧的 17 条，其余走 `name.slice(0,3).toUpperCase()` 兜底，切出 `R&B`（含 `&`）、`实验电` / `风格补` / `摇滚与`（中文截断），并让 `ELE`、`CHI` 各重复一次。补遗类统一用 `X` 前缀区分于正式大族，现在 24/24 全覆盖、零重复。`check-spectrum-codes.mjs` 把这条断言固化了。

**算「位置」时别拿常量当参照系。** 信号链的 A/B 读数会判断两套顺序是否「听起来不一样」，原实现写成 `CHAIN_IDS.filter(id => order.includes(id)).indexOf(id)` —— 用固定的默认顺序去过滤，两个槽位算出来的名次恒等，函数永远返回 false，于是界面一直说「两套顺序听起来几乎一样」，哪怕一套是失真在前、另一套是混响在前。名次必须是**在那个数组内部的下标**（`order.indexOf(id)`）。这类错误不看输出是发现不了的：函数不报错，只是安静地恒为假。

**「补遗」是编辑性分组，不是音乐分类。** 为补覆盖度，分类库末尾追加了 5 个收纳桶（风格补遗、摇滚与极端风格补遗等），桶内条目各自有正确上位关系（如 Psybient → Ambient）。如果直接当大族渲染，它们会和 House、Techno 并列出现在信号条与分类树上，读起来像「补遗」也是一种风格。现在解析层给它们打 `supplement` 标记，页面分三个区展示（正式大族 / 补充收纳桶 / 待归档），统计口径也拆成 `families` 与 `supplementFamilies`。

**给单行 flex 里的元素设 `min-width` 等于给视口设下限。** 频谱条是 `flex: 1 1 0` 加 `min-width: 12px`，16 条时没事，24 条就要 360px 以上，窄屏直接溢到 446px > 320px。窄屏下必须放开 `min-width: 0`，代号放不下就交给下方图例承载名称。

**线上是另一个源，iframe 拿不到 `contentDocument`。** 线上验证改用 CDP（`live-check.mjs` / `live-mobile.mjs`）：Node 22 自带 `WebSocket` 和 `fetch`，`spawn` 一个带 `--remote-debugging-port` 的 Chrome，从外部发 `Runtime.evaluate`，不受同源策略限制，还能通过 `Runtime.exceptionThrown` 抓到真实运行时报错，不需要 puppeteer。

**别假设所有模块都是格子型。** 节拍/鼓组/低音/旋律是步进格（48 或 64 格），但**和弦是「进行选择器」没有 `.st-cell`**，音色是推子。判定「挂载成功」要看面板是否真有内容上屏，不能数格子。
