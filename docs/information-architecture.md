# 电音制作学习站信息架构 / Information Architecture

## 1. 设计目标

网站服务于一个明确目标：**学会做电子音乐**，而不是只学会描述风格。参考 Ableton Learning Music 的“先试听、再理解、马上动手、得到反馈”，但把主线改成真实制作流程：

- **制作课**：按做歌的先后顺序推进，每课有学完能做到什么、要在 DAW 里留下什么、先修哪一课。
- **知识库**：可检索、可回源、可沿关系追踪，解决“这个声音/概念是什么、为什么这样做”。
- **练习与实验室**：为制作服务的听感训练与音色试错，不是独立的小游戏。

课程和知识库共用同一套内容源与浏览器实时合成音频。课程决定顺序，知识库决定依据；知识库不从属于课程，课程也不复制知识库正文。

导航收敛为六个入口：**制作课 / 工作室 / 知识库 / 图谱 / 练习 / 实验室**。首页通过品牌标识返回；来源、全库检索、知识库模块与历史/现场/术语/听辨/制作指南放在页脚、移动端菜单次级区或知识库专题页。已有进度时，顶部出现进度胶囊，直接回到下一课。

### 2.1 视觉与交互语法

- **主题**：Club Rig / Soundsystem。页面被当作一套扩声系统：页头是机架单元，进度是步进尺，实验室是通道条，播放条是波形。
- **色彩即信号**：琥珀 = 当前位置 / 主操作 / 已完成；洋红 = 下一课 / 正在播放 / 需修正；冰蓝 = 参考信息 / 独奏；大族色相按音域排序，只出现在边线与圆点上。
- **字体**：窄体展示字承担标题和大号阶段编号；系统无衬线承担正文；等宽字承担 BPM、阶段、通道与时间码；数字统一等宽。
- **节奏结构**：页头底部是 16 分格 transport 标尺，播放时播放头随音频推进；课程进度是 22 格、按 8 阶段分组的步进尺；练习、图谱、实验室复用「格 / 通道」语义。
- **主动效**：页头 12 段电平表读取主总线真实 FFT，播放时实时跳动；鼓机播放头、结构播放器高亮与指示灯按当前 BPM 换算节拍；其余为 step 曲线的页面切换、悬停与完成反馈。全部尊重 `prefers-reduced-motion`。
- **反馈**：勾选自检清单会实时更新完成按钮上的「自检 n/m」；完成课时写入本地进度、更新顶部胶囊、弹出带“下一课”的 toast；底部操作条保证完成与翻页始终可达。

### 2.2 页面层级收敛

- 首页保留唯一的完整 Hero；内页统一使用紧凑页头（编号 / 标题 / 说明 / 三个关键数字 / 单一主操作）。
- 每个页面只有一个主行动：制作课 = 继续下一课；知识库 = 全库检索；图谱 = 搜全库；实验室 = 播放；练习 = 作答。
- 重复解释性区块（如「知识不是孤岛」三卡）收敛为一行注释，把空间让给可操作内容。

## 3. 制作课模块

### 3.1 课程结构

课程按“先能出声，再能成立，最后能完成”排列。阶段顺序来自制作依赖，而不是学科目录：

| 阶段 | 主题 | 阶段产出 | 课时 |
| --- | --- | --- | --- |
| 00 | 准备与信号链 | 建立一份可用的工程模板，并画出自己的声音信号链 | DAW、轨道与工程模板；MIDI、音源、效果器与总线 |
| 01 | 鼓组与律动 | 写出一个 8 小节鼓组，并能让它在重复中保持变化 | 写出第一组 4/4 鼓；切分、留白与 Half-time；鼓组层次与处理 |
| 02 | 低频与 Bass | 做出 Kick 与 Bass 不打架、在大小音箱都能听清的低频段 | Kick 与 Bass 如何让位；Bass 的四种性格；低频控制 |
| 03 | 和弦与情绪 | 写出一个 4 小节和弦循环，并能用音色改变它的情绪 | 四小节和弦进行；Supersaw、Pad 与和弦音色 |
| 04 | 旋律与音色设计 | 完成一个 8 小节 Drop 草案：鼓、Bass、和弦、Lead 各就各位 | Lead 与 Hook；合成器四步；采样与人声切片 |
| 05 | 编曲与能量 | 做出一个 2 分钟的结构草图：Intro → Breakdown → Build → Drop → Outro | 八段结构；转场；自动化与能量曲线 |
| 06 | 混音与空间 | 完成一版平衡的粗混：各层清楚、低频稳定、没有明显过载 | 增益结构与总线；EQ 与频段让位；混响、延迟与立体声 |
| 07 | 完成一首歌 | 导出一首 2 分钟左右的电子音乐 Demo，并写一份复盘 | 项目一：House Loop；项目二：Trap / Dubstep；结构收束、导出与复盘 |

每课固定结构：

1. **产出（outcome）**：学完能做到什么，用行动描述。
2. **概念**：最多几段文字，只讲完成这一课所需的最小学理。
3. **互动**：至少一个可播放/可操作组件，先建立听感。
4. **任务（task）**：明确、可完成，能在 DAW 或站内立刻做。
5. **交付物（deliverable）**：这一课要留下的具体东西，例如一段 8 小节鼓、一版粗混、一个 2 分钟 Demo。
6. **自检清单（goals）**：课末逐条对照，决定是否可以标记完成。
7. **知识库（kbLinks）**：3–5 个相关条目/文档，用于回查原理。
8. **前置课（prerequisites）**：指向更早的课时；未完成时提示先补，不硬锁。

### 3.2 课时数据模型

```js
{
  id: "kick-and-bass",
  title: "Kick 与 Bass 如何让位",
  subtitle: "Sidechain、Sub Bass 与低频冲突",
  minutes: 7,
  outcome: "能用 Sidechain 或音符编排，让 Kick 与 Bass 不抢同一瞬间。",
  deliverable: "一段 8 小节鼓组 + Bass；Kick 落下时 Bass 明显让位。",
  prerequisites: ["drum-processing"],
  goals: ["听出低频冲突", "用 Sidechain 或编排解决"],
  concept: ["...", "..."],
  keyTerms: ["Sidechain", "Sub Bass", "Kick"],
  widget: { type: "lab", bpm: 124, groups: { drums: true, bass: true } },
  task: "给 Bass 加 Sidechain，或把 Bass 音符挪开 Kick；A/B 对比冲突感。",
  kbLinks: ["instrument:bass-bassline", "glossary:sidechain", "glossary:sub-bass"],
  links: [{ label: "去音色实验室", href: "#/lab" }]
}
```

支持的互动类型：

| type | 组件 | 用于 |
| --- | --- | --- |
| `metronome` | BPM 可调节拍器 | 工程速度、拍与小节 |
| `sequencer` | 8 步 × 3 行鼓机 | 写出 4/4 鼓组 |
| `compare` | 2–3 个风格试听按钮 | 律动、Bass 性格、Lead、转场对比 |
| `lab` | 七组音色开关 + BPM | 鼓组层次、低频让位、和弦音色、混音分层 |
| `structure` | 八段结构播放器 + 高亮 | 结构草图、自动化与能量 |
| `chords` | 四个和弦试听 | 和弦进行与色彩 |
| `none` | 无音频 | 信号链等阅读课 |

进度：

- `localStorage` 键：`em-course-progress-v1`。
- 记录已完成 lesson ID 数组；加载时过滤掉当前课程中不存在的旧 ID。
- 课程地图、课时侧栏、首页“继续学习”共享同一进度。
- 不锁课；前置课只提示，不做强制测验。
- 阶段进度 = 该阶段已完成课时 / 该阶段总课时。

### 3.3 阶段元数据与进阶关系

每个阶段除 `title / description / outcome` 外，还声明四项，直接决定课程页的呈现：

| 字段 | 含义 | 页面位置 |
| --- | --- | --- |
| `tier` | `基础` / `进阶` / `完成` 三档 | 路线带分组、阶段标题上方 |
| `short` | 两字短名（准备 / 鼓组 / 低频 …） | 路线阶梯的阶段块 |
| `entry` | 进入该阶段前必须具备的能力 | 阶段卡片右栏 |
| `knowledge` | `{ label, kb }[]`，本阶段知识点 | 阶段卡片左栏，chips 链到知识库 |
| `exit` | 阶段验收标准 | 阶段卡片右栏 |

难度带与进阶顺序：

```text
基础  00 准备与信号链 → 01 鼓组与律动 → 02 低频与 Bass
      （产出：一个能循环、有低频支撑的 8 小节 Loop）

进阶  03 和弦与情绪 → 04 旋律与音色设计 → 05 编曲与能量
      （产出：一段有 Drop、有结构起伏的 2 分钟草图）

完成  06 混音与空间 → 07 完成一首歌
      （产出：一版粗混 + 一首导出的 2 分钟 Demo 与复盘）
```

三条难度带不是标签，而是依赖边界：`entry` 引用的能力由前一阶段产出，`exit` 又成为下一阶段的 `entry`。当前 8 个阶段共 **45 个知识点**，全部指向 `data/kb.json` 或 `data/web.js` 中真实存在的条目/文档（构建时校验）。

### 3.4 课时页的五个区块

课时内容固定为带编号的五块，顺序即学习顺序：

1. `01 概念` — 最小学理，段落宽度 ≤ 66 字符。
2. `02 先听` — 站内可播放组件（无组件时该块自动省略，编号顺延）。
3. `03 动手` — DAW 任务。
4. `04 自检` — 可勾选清单，实时反映在完成按钮上。
5. `05 回查` — 相关知识库条目/文档。

### 3.6 工作室项目模型

工作室不是课程的一部分，而是课程的练习场。它维护一个独立的项目对象，字段与音频引擎一一对应：

| 字段 | 含义 | 被谁消费 |
| --- | --- | --- |
| `bpm` / `swing` | 速度与摇摆量 | 会话时钟、延迟时值 |
| `chords[]` | 四小节的和弦名 | 和弦播放、**低音根音** |
| `drums{kick,clap,hat,openhat}` | 4×16 布尔网格 | 鼓组 voice |
| `bass[3][16]` | 和弦音偏移（0/7/12） | Bass voice，按小节取根音 |
| `melody[8][16]` | 音阶级数（0–7） | 旋律 voice，按项目音阶取音高 |
| `sound{}` | 滤波/共振/失真/延迟/混响/音色 | 总线效果链、voice 参数 |
| `structure[]` | 段落类型 + 小节数 | 播放时决定哪些层发声 |
| `module` | 上次停留的模块 | 恢复现场 |
| `done{}` | 各模块是否被亲手编辑过 | 进度环与导航徽标 |

**衔接规则**（这是模块之间真正的耦合点）：

1. `bass` 只存相对偏移，根音来自 `chords[bar]`，所以改和弦必然改低音。
2. `melody` 只存级数，音高由 `scaleIntervals` + `base` 算出，所以永远在调内。
3. `sound` 作用在总线上，六个模块共享同一套滤波与空间。
4. `structure` 不改内容，只在播放时按 `layers` 静音未启用的层。

**进度判定**：`done` 由交互事件写入（点格子、选和弦、拉推子、改结构），而不是由内容是否满足条件推出。理由是示范工程本身已完整，条件判定会让首次进入就显示 5/6。

### 3.5 前置关系

先修关系是一条链，跨阶段也跨课：

```text
daw-and-tracks → signal-chain-basics → drum-programming
→ drum-processing → kick-and-bass → bass-sound-design → low-end-control
→ chord-progressions → chord-texture → lead-hook → synth-controls → sampling-chops
→ structure-eight → transitions → automation-energy
→ gain-stage → eq-space → space-stereo
→ project-house → project-bass → finish-export
```

部分课时有分支（例如 `groove-and-half-time` 与 `drum-processing` 都依赖 `drum-programming`，但前者不阻塞低频阶段）。课时页只显示直接前置课；课程地图按阶段顺序展开。

## 4. 知识库模块

- 内容：1376 个分类条目、158 个知识文档、1541 个检索分块、24 个正式大族 + 5 个补充收纳桶。
- 检索：浏览器内同源 BM25（中文单字/双字切分，字段加权，大族/类型/BPM 过滤）。
- 入口：
  - 搜索框（全库检索）
  - 风格图谱（结构层级 + 上下位关系）
  - 大族/条目/文档详情
  - 专题页（听辨、制作、历史、现场、术语）
- 详情页的两类关系标签：
  - 上位 / 下位：影响与衍生。
  - Related To / A.K.A.：相似与别名。
- 每个条目/文档都可反向显示“在课程中学习”。

## 5. 知识库如何优化学习逻辑

知识库不是课后参考书，而是课程顺序与验收标准的依据。

### 5.1 用制作依赖决定顺序

课程顺序不按风格年代或百科分类，而按“下一步需要什么”：

1. 没有工程与轨道，就无法写鼓。
2. 没有稳定鼓组，就无法判断低频是否让位。
3. 没有低频，就无法判断和弦与 Lead 是否挤占频段。
4. 没有完整 Loop，就无法做结构与转场。
5. 没有结构，就无法做有意义的混音决定。
6. 没有粗混，就无法完成导出与复盘。

知识库中的信号链、七组音色、八段结构、频段分工等文档，为这些依赖提供解释；课程只引用其中完成当前任务所需的部分。

### 5.2 用 `kbLinks` 把概念钉回知识库

- 每课 `kbLinks` 声明相关条目/文档 ID。
- 课时页渲染为可点击 chips：
  - 条目 ID → `#/genre/:id`
  - 大族 ID → `#/family/:id`
  - 文档 ID → `#/doc/:id`
- 课时页还提供“在全库中继续查”，把课程标题作为检索词。
- 链接覆盖课程中的关键名词：MIDI、Track、Oscillator、Filter、ADSR、LFO、Compressor、Bus、EQ、Sidechain、Sub Bass、Supersaw、Pad、Reverb/Delay、Wavetable 等；第一批 43 个唯一目标、84 次引用，全部由构建产物校验存在。

### 5.3 用知识库反查课程

- 构建 `COURSE_KB_LINKS`：`kbId → lessons[]`。
- 构建别名映射 `COURSE_KB_ALIASES`：
  - 风格文档的 `metadata.entryId`（如 `style:bigroom-house → g-1581`）
  - 大族文档的 `metadata.familyId`（如 `family:house → f-165`）
- 因此访问 `g-1581` 也能看到关联到 `style:bigroom-house` 的课程。
- 条目页、文档页显示“在课程中学习”chips。
- 全库检索页显示 `COURSE / 相关课程` 面板，使用 `searchLessons(query)` 匹配课时标题、概念、关键词和 `kbLinks` 标签。

### 5.4 用产出与清单定义“学会”

- `outcome` 回答“学完能做什么”。
- `deliverable` 回答“要留下什么文件/片段”。
- `goals` 变成本课自检清单。
- 三者都不由知识库自动生成，但术语与判断标准来自知识库文档；课程是编辑层，知识库是依据层。

### 5.5 练习 / 实验室 → 课程

- 练习页回答后提示回到相关课时或“音色实验室”。
- 课程中的 `metronome`、`sequencer`、`lab`、`structure` 与练习/实验室复用同一个 Web Audio 引擎。
- 实验室的七组开关与课程“七组音色如何叠”“混音分层”使用同一组分组定义。

## 6. 核心交互流程

### 6.1 第一次来

`首页（可先改一格鼓机再播放）→ 开始第一课 → 制作课地图 → 课时 00 → 建工程模板 → 底部操作条标记完成 → 课时 01 鼓组 → …`

每一步都先看本课产出，再播放示例，最后去 DAW 完成任务并对照交付物。完成反馈在同一屏内出现，不需要回课程地图确认。

### 6.2 带着问题来查

`首页/导航 → 知识库 → 搜索/图谱 → 条目或文档 → 在课程中学习 → 进入对应课时`

例如搜“Sidechain” → 术语条目 → 看到“在课程中学习：Kick 与 Bass 如何让位” → 回到课时。

### 6.3 卡住时补前置

`课时页 → 前置课提示（缺失）→ 先修课时 → 完成 → 返回原课时`

不硬锁，但用户知道该补哪一课，而不是在混音阶段回头补鼓组。

### 6.4 学完一课想继续

`课时 → 底部操作条直接下一课`
`课时 → 相关知识库 → 文档/条目 → 回到课程；顶部进度胶囊始终指向下一门未完成课`
`课时 → 练习 / 实验室 → 继续做同类任务`

### 6.5 复习

`制作课地图（阶段进度）→ 已完成课时 → 重听示例 / 重做任务`
`知识库搜索 → 相关课程 → 回看对应课时`

## 8. 边界与原则

- 课程是编辑内容，不是自动生成的；知识库是数据层。
- 课程按制作流程排序，不按风格百科排序；风格内容用于听辨、参考与项目选题。
- 课程不锁课、不强制测试；用“交付物 + 自检清单 + 完成标记”建立节奏。
- 所有试听为合成示例，不是原曲；不能替代原曲欣赏。
- 课程不替用户操作 DAW；站内组件用于建立听感与结构感，真实产出在用户自己的工程里。
- 知识库分类保留原文档的编辑立场与未完成状态，不为了课程叙事而“修正”原文。
- Agent 模块继续只提供知识检索；课程进度与课程 UI 属于网页层。
