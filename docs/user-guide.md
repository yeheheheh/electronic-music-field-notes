## 2. 网页使用手册

### 2.1 导航结构

一级导航按意图收敛成四个字：**听 / 查 / 练 / 做**——听是「我想知道这是什么」，查是「我想查一个词」，练是「我想练耳朵」，做是「我想自己做」。点品牌标识回首页。图谱、工作室、实验室、DJ 工具、全库检索、来源与勘误都在页脚与移动端二级菜单里。

完整路由表：

| 路由 | 页面 | 主要用途 |
| --- | --- | --- |
| `/` | 首页 | 四轨入口（听 / 查 / 练 / 做）+ 每轨微可视化；单小节鼓机；「今天听这条」可直接播 8 秒 |
| `#/listen` | 听 | 三问筛选（多快 / 鼓怎么落地 / 低音）+ 4 × 4 速度×律动矩阵；点任意风格立即试听并出卡 |
| `#/quick` | 现场速查 | 一屏一个风格，左右滑动切换；Service Worker 缓存后断网可用，可请求屏幕常亮 |
| `#/dj` | DJ 工具 | 过渡检查（BPM / 律动 / 低频三条规则）、BPM 邻接表、现场判定 |
| `#/card/:id` | 风格卡 | 一张 1080 × 1440 的图 + 播放入口，给「发链接」用 |
| `#/learn` | 制作课地图 | 8 阶段 22 课总览；三条难度带（基础 00–02 / 进阶 03–05 / 完成 06–07）；22 格刻度可点击跳课；可「只看未完成」 |
| `#/learn/:id` | 课时页 | 本课产出、五区块内容、自检清单、前置课提示、相关知识库、底部操作条 |
| `#/library` | 知识库主页 | 全库检索入口、六大知识工具、大族概览、双模块关系说明 |
| `#/search` | 全库检索 | 覆盖条目、大族、指南、术语、乐器组、历史、现场与来源；同时显示相关课程 |
| `#/atlas` | 风格图谱 | 24 个正式大族 + 5 个补充收纳桶 + 1 个待归档分组；搜索、BPM 筛选、分类树、随机条目 |
| `#/family/:id` | 大族页 | 大族简介、下级分类、「这一族的声音」（可直接试听） |
| `#/genre/:id` | 条目页 | 顶部是听感卡（一句人话 + 三个听点 + 8 秒试听 + 分享），下面是别名、上下位、相似风格、结构下级、例曲与原文行号 |
| `#/doc/:id` | 文档页 | 任意模块文档的完整正文、来源、BPM、所属大族、Agent ID 与相关课程 |
| `#/practice` | 练习 | 风格听辨四选一 + BPM 估速，带得分与连对反馈 |
| `#/lab` | 实验室 | 七组音色（打击乐 / 贝斯 / 和弦 / 人声 / 主奏 / 氛围 / 音效）实时开关，BPM 100–160 |
| `#/guide/listen` 等 | 专题页 | 听辨入门、结构与音色、历史、现场、术语、图谱说明 |
| `#/module` | 知识库模块 | 模块统计、CLI / MCP / HTTP 接入方式、来源快照与本地 API 检测 |
| `#/about` | 来源与勘误 | 全部资料来源、转写校正表、数据规模、使用与版权说明 |

### 2.1.1 只想先听懂：从「听」进入

如果你不确定自己听到的是什么，别从图谱开始——那里是给查资料的人用的。

1. 打开 `#/listen`，按顺序回答三个问题：**多快**（慢 / 中 / 快 / 极快）、**鼓怎么落地**（每拍一脚 / 两拍一下 / 碎的 / 切开的）、**低音**（一直垫着 / 一下一下 / 拖得很低 / 在抖 …）。三个条件会同时收窄矩阵。
2. 矩阵里点任意一个风格，右边立刻出卡并开始播 8 秒。卡片上是：一句人话、三个听点（鼓 / 低音 / 空间）、什么时候会听到。选中的风格和三个条件都会写进地址栏，从条目页返回或刷新都还在。
3. 想只听低音就把「鼓」关掉——分层是真操作，不是形容词。
4. 点「做成卡片」，得到一张 1080 × 1440 的图，手机上长按保存，直接发进群里。
5. 到了现场用 `#/quick`：一屏一个风格，左右滑动；第一次打开后即使断网也能用。
6. 想听原曲：条目页的例曲点「试听 30 秒」——能播的是 Apple Music 的官方预览，没有的话旁边有 B 站 / 网易云的搜索链接。

想接歌就去 `#/dj`：选 A 和 B，它给速度差、律动差、低频冲突，以及三条具体动作，每条都链到过渡课和对应词条。

### 2.1.2 首页怎么读

首页不是目录，是四个入口：**听**（不知道这是什么）、**查**（想查一个词）、**练**（想练耳朵）、**做**（想自己做）。每块面板下面是三条直达链接，右下角的「今天听这条」每天换一条 92 个风格里的试听，点播放就能听。

### 2.2 第一次来：跟着制作课走

推荐路径：**首页 → 开始第一课 → 课程地图 → 课时 → 播放示例 → 在 DAW 完成任务 → 对照交付物与自检清单 → 标记完成 → 下一课**。

课时页内容固定为五个带编号的区块，顺序即学习顺序：

1. `01 概念` — 完成这一课所需的最小学理。
2. `02 先听` — 站内可播放组件（节拍器 / 鼓机 / 对比试听 / 分层实验室 / 结构播放器 / 和弦试听）。
3. `03 动手` — 可以立刻在 DAW 或站内完成的任务。
4. `04 自检` — 可勾选清单，实时反映在完成按钮上的「自检 n/m」。
5. `05 回查` — 相关知识库条目/文档，用于回查原理。

课时页侧栏显示学习进度、前置课与阶段大纲；底部固定操作条保证「上一课 / 完成 / 下一课」始终可达。前置课未完成时会提示先补哪一课（不硬锁课）。

### 2.3 带着问题查：知识库

推荐路径：**知识库 → 搜索 / 图谱 → 条目或文档 → 「在课程中学习」 → 回到对应课时**。

例如搜「Sidechain」→ 术语文档 → 看到「在课程中学习：Kick 与 Bass 如何让位」→ 回到课时。反过来，课时里的 `kbLinks` 也全部链回条目或文档；全库检索页还会用课程标题、概念与关键词匹配出「相关课程」面板。

### 2.4 练习与实验室

- **练习（`#/practice`）**：风格四选一与 BPM 估速两种模式，带得分、连对与即时反馈；作答后会建议回到相关课时。片段全部是合成循环。
- **实验室（`#/lab`）**：七个通道条（打击乐 / 贝斯 / 和弦 / 人声 / 主奏 / 氛围 / 音效）可实时开关，BPM 在 100–160 之间调整。建议先全关，再一层层加回来，边听边理解层次与频段分工。通道上的 `S` 按钮独奏单层，另有全开 / 全关按钮。

### 2.5 键盘操作

| 按键 | 位置 | 作用 |
| --- | --- | --- |
| `/` | 任意页面 | 打开全库搜索（在输入框内输入时除外） |
| `Esc` | 任意页面 | 关闭搜索浮层 / 移动端菜单 |
| `1`–`4` | 练习（风格题） | 选择答案 |
| `空格` | 练习 | 重听片段 |
| `回车` | 练习 | 下一题 |
| `1`–`7` | 实验室 | 开关对应通道 |
| `S` | 实验室 | 退出独奏（独奏通过通道上的 `S` 按钮切换） |

### 2.6 声音与学习进度

- **首次播放需要一次点击**（浏览器自动播放策略）；页头右侧可随时静音，底部播放条提供进度与音量。切换页面时播放状态保持。
- 所有试听由 Web Audio 实时合成，**不使用原曲录音**，也没有音频文件可下载。
- 进度保存在浏览器 `localStorage`：`em-course-progress-v1`（已完成课时）与 `em-lesson-checks-v1`（自检勾选）。**没有账号或后端同步**，换浏览器或清缓存会丢失；加载时会自动过滤已不存在的旧课时 ID。
- 页面适配桌面、平板与手机，并尊重 `prefers-reduced-motion`。

## 3. 知识库阅读指南

### 3.1 里面有什么

| 维度 | 规模 |
| --- | --- |
| 大族 | 24 个正式大族 + 5 个补充收纳桶 + 1 个待归档 |
| 条目 | 1376 个（1357 活跃 + 19 归档），其中 90 个为内容很少的待完善/交叉引用条目 |
| 关系链接 | 4374 条（上位 / 下位 / 相似） |
| 例曲索引 | 1654 条（文字索引，无音频） |
| BPM 覆盖 | 181 个条目（仅原文明确写出数字的） |
| 知识文档 | 158 个（听辨、制作、历史、现场、术语、来源等精编文档） |
| 检索分块 | 1541 个 |
| 来源文件 | 7 个（飞书分类库、B 站《电音圣经》4 期、播客《多新鲜呐》ep31、转写校正） |

内容分两层：**分类库原文**（来自《电音风格项目丨第四期》，保留原文档的编辑立场与未完成状态）与**精编内容**（听辨、制作、历史、现场、术语等二次整理文档）。两者都可在条目/文档页溯源。

### 3.2 推荐阅读顺序

- **想先建立听感**：专题页「听辨入门」（`#/guide/listen`）→ 十种风格试听（Bigroom House、Electro House、Deep House、Uplifting Trance、Techno、Trap、Future Bass、US Dubstep、Hardstyle、Future Rave）→ 风格图谱（`#/atlas`）→ 按大族浏览条目。
- **想学做歌**：以制作课为主轴，知识库只做回查（见 2.2、2.3）。
- **想读原始资料**：直接读 [sources/feishu-genre-project-phase4.md](../sources/feishu-genre-project-phase4.md)；条目页的「来源行号」可以直接定位到原文对应行。

### 3.3 条目页解剖

| 字段 | 含义 |
| --- | --- |
| `id`（如 `g-1581`） | 由原文行号生成；重新排版原文会让 ID 变化 |
| 别名（A.K.A.） | 同一风格的其它叫法，检索时按 4 倍权重参与匹配 |
| 所属大族与路径 | 面包屑形式的层级路径，用于区分同名条目 |
| BPM | 原文明确写出的速度范围；没有数字则留空 |
| 解释正文 | 来自原分类库的条目解释，保留原文状态 |
| 例曲 | 文字索引（曲名 / 艺术家），不提供音频 |
| 关系 | 上位 / 下位 / 相似（Related To），均可点击跳转 |
| 来源行号 | 指向 `sources/` 原文副本的行号，用于溯源 |
| 状态标记 | `待完善` / `交叉引用` / `待归档` / `已合并` 原样保留，不替原文补写 |

### 3.4 关系怎么理解

- **上位 / 上**：影响来源——这个风格从哪些更早的风格演化而来。
- **下位 / 下**：衍生方向——从这个风格又发展出了什么。
- **Related To**：相似风格，没有明确演化方向。
- **A.K.A. / AKA**：别名。

### 3.5 文档类型

检索与数据中的 `type` 字段可能为：`entry`（条目）、`family`（大族）、`guide`（精编指南）、`style`（风格专题）、`instrument`（乐器组）、`glossary`（术语）、`timeline`（历史）、`live`（现场）、`source`（来源元数据）。`transcript`（转写原文）默认不进入检索，避免 ASR 噪声。

### 3.6 检索技巧

- **中英混合直接搜**：`uplifting trance`、`808 bass`、`七组音色怎么分工` 都可以。
- **字段加权**：标题 6×、别名 4×、大族/路径与例曲 2×、正文 1×——所以记得风格名时，最相关的结果会排最前。
- **过滤**：结果可按大族、类型、BPM 区间（`bpm_min` / `bpm_max`）筛选；BPM 过滤只对原文写出数字的条目生效。
- **去重规则**：长文档可能拆成多个分块，但结果按条目/文档去重；返回的 `count` 是去重后的候选总数。
- **快捷入口**：任意页面按 `/` 直接打开全库搜索。

### 3.7 溯源与勘误

- 每个条目/文档都带 `source`（来源 ID、标题、行号）。行号指向 `sources/` 里的原文副本或转写文件，可逐行核对。
- 转写校正表与全部来源链接在「来源与勘误」页（`#/about`）。《电音圣经》第 03 期无公开字幕，使用本机 Whisper（`ggml-base`）对公开视频音频做本地转写，仅用于核对内容，个别例曲名称因转写不清未采用。
- 引用时建议**优先引用原始文档与视频**，本库只是整理；引用本库内容时注明来源与行号。

### 3.8 阅读时的数据状态提醒

- 90 个条目内容很少，部分只是指向其他板块的交叉引用；72 组同名或近名条目分布在不同大族，用「所属大族 + 路径」区分。
- 分类是有立场的民间整理，不是音乐产业标准；同一声音在不同城市、厂牌、社群会有不同叫法。
- 例曲只提供文字索引，版权归原作者；本库不是音乐下载站。

## 4. 给 AI Agent 用（知识库模块）

`kb-module/` 是一个零依赖、可独立构建运行的模块：Node.js ≥ 18 即可，无 npm 依赖、无数据库、无网络请求。网页与 Agent 共用同一份知识库产物，不是两套内容。

### 4.1 三步上手

```bash
cd kb-module

node bin/kb.mjs build     # 构建产物到 dist/（读取 config/kb.config.json）
node bin/kb.mjs verify    # 校验产物完整性
node bin/kb.mjs search "uplifting trance" --limit 3   # 检索

node bin/kb.mjs context "七组音色怎么分工" --max-chars 4000   # 生成 prompt 上下文
npm test                  # 跑测试（11 项：构建/检索/CLI/MCP/HTTP）
```

### 4.2 MCP 接入（推荐）

把 `kb-module/agent/mcp.config.example.json` 里的占位符替换为**绝对路径**，合并进客户端（Claude Desktop / Qoder 等）的 MCP 配置：

```json
{
  "mcpServers": {
    "electronic-music-kb": {
      "command": "node",
      "args": [
        "<仓库绝对路径>/kb-module/bin/mcp-server.mjs",
        "--dist",
        "<仓库绝对路径>/kb-module/dist"
      ]
    }
  }
}
```

如果客户端找不到 `node`，把 `command` 改成 node 的绝对路径（Windows 常见为 `C:/Program Files/nodejs/node.exe`）。配置后先用 `kb_manifest` 测通。

MCP 工具共 5 个：

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| `kb_search` | `query` 必填；`limit`、`family`、`type`、`bpm_min`、`bpm_max` | JSON 检索结果 |
| `kb_context` | `query` 必填；`limit`、`max_chars`、过滤同上 | Markdown 上下文（可直接拼进提示词） |
| `kb_get` | `id` | 条目/文档完整 JSON |
| `kb_families` | 无 | 大族列表 |
| `kb_manifest` | 无 | 版本 / 统计 / 来源 |

### 4.3 CLI 速查

```bash
node bin/kb.mjs build [--config path] [--out dir]
node bin/kb.mjs search "query" [--limit 6] [--family House] [--type entry] [--bpm-min 120] [--bpm-max 135] [--json]
node bin/kb.mjs context "query" [--limit 5] [--max-chars 6000] [--json]
node bin/kb.mjs get g-1581 [--json]
node bin/kb.mjs families [--json]
node bin/kb.mjs manifest
node bin/kb.mjs verify
node bin/kb.mjs serve [--port 8787] [--host 127.0.0.1]
node bin/kb.mjs mcp [--dist dir]
```

所有命令支持 `--dist <dir>` 或环境变量 `KB_DIST` 指定产物目录；输出走 stdout、错误走 stderr、退出码非零，适合被 Agent 当作 shell 工具调用。

### 4.4 HTTP API 速查

```bash
node bin/kb.mjs serve --port 8787
curl "http://127.0.0.1:8787/search?q=uplifting%20trance&limit=3"
curl "http://127.0.0.1:8787/context?q=808%20bass&format=text"
```

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查、版本、统计 |
| GET | `/manifest` | 完整 manifest |
| GET | `/families` | 大族列表 |
| GET / POST | `/search` | 检索；GET 用查询串，POST 用 JSON body |
| GET | `/context` | 上下文 JSON；`format=text` 返回 Markdown |
| GET | `/get?id=...` 或 `/entry/:id` | 条目/文档详情 |

默认只绑定 `127.0.0.1`。**不要无鉴权地暴露到公网**；确需远程访问时，应在前面加认证反向代理。

### 4.5 推荐调用顺序与引用规范

1. `kb_manifest` 确认版本与数据规模 → 2. `kb_families` 确定范围（可选）→ 3. `kb_context` 拿回答所需上下文 → 4. 需要完整条目/关系/例曲时再 `kb_get` → 5. 最终回答中用 `[ID]` 引用来源，资料不足时明确说明，不要补造。

系统提示词与 OpenAI 工具定义在 `kb-module/agent/system-prompt.md` 与 `agent/openai-tools.json`，可直接用于 function calling 场景。

### 4.6 独立移植

复制整个 `kb-module/` 到目标机器 → 确保 Node.js ≥ 18 → `node bin/kb.mjs build` → `node bin/kb.mjs verify` → 配置 MCP 或 HTTP。`dist/` 可以随模块一起复制，接收方甚至可以不重新构建。

## 5. 更新与再生成数据

- **知识库**：改 `kb-module/inputs/`（`taxonomy.md` 分类库、`curated.json` 精编内容、`transcripts/` 转写、`source-map.json` 来源）后运行：

```bash
node kb-module/bin/kb.mjs build   # 只构建 Agent 模块
node scripts/build-data.mjs       # 构建模块 + 同步网页数据（data/kb.json、kb.js、curated.js、web.js、genres.csv）
```

- **课程**：`data/course.js` 是手工编排的编辑层，不由模块生成；改课时/任务/产出/`kbLinks` 后刷新页面即可，无需重新构建知识库。知识库更新后若改名了课程引用的条目，需要同步检查 `kbLinks`。
- **过期判断**：`kb-module/dist/manifest.json` 里记录了每个输入文件的 SHA-256（`sourceHashes`）；构建时间见 `builtAt`。
- **Agent 端**：重建后需重启 MCP 进程（或客户端重连）以加载新索引。
- **生成物不要手改**：`data/*` 与 `kb-module/dist/*` 都是构建产物；输入在 `inputs/`，构建逻辑在 `kb-module/lib/`。

## 6. 常见问题 FAQ

**Q：双击打开后点播放没声音？**
浏览器不允许自动播放，首次需点击一次「播放 / 试听」按钮；同时检查页头右侧是否处于静音。若浏览器不支持 Web Audio，按钮会提示不可用，但文字、图谱与检索仍正常。

**Q：直接双击 `index.html` 能用吗？**
可以。数据以 JS 文件加载，全部资源本地化，支持 `file://`。若遇到个别浏览器的本地文件限制，用 `node scripts/serve.mjs` 起本地服务器（默认 5501 端口；端口被占用时可 `PORT=5502 node scripts/serve.mjs`）。

**Q：学习进度会同步吗？**
不会。进度只存在当前浏览器的 `localStorage`，没有账号与后端；换浏览器、换设备或清缓存会丢失。

**Q：检索结果里出现同名条目，怎么选？**
用「所属大族 + 层级路径」区分（72 组同名/近名条目分布在不同大族）。打开条目页看面包屑最直接。

**Q：搜不到某个风格？**
当前是词法检索（BM25）而非语义检索，试试别名或英文名；中文查询做了单字+双字切分，超短查询可能召回偏宽。风格确实不存在时，图谱里按大族翻。

**Q：MCP 客户端连不上 / 找不到 node？**
把配置里的 `command` 换成 node 绝对路径，`args` 用绝对路径；先用 `node kb-module/bin/mcp-server.mjs --dist kb-module/dist` 在终端验证能启动（stdout 只输出 JSON-RPC 是正常的）。

**Q：改了 `inputs/` 后网页没变化？**
网页数据需要同步：跑 `node scripts/build-data.mjs`（只跑 `kb-module` 的 build 不会更新 `data/`）。

**Q：为什么没有原曲试听？**
版权。所有试听是 Web Audio 实时合成示例，用于展示节奏、音色与结构差异，不能替代原曲欣赏。
