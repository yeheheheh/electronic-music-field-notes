# 分支树导航方案 / BRANCH TREE NAVIGATION

> 借鉴 Ishkur's Guide to Electronic Music 的核心体验，为「电音档案」增加一种**看得见分叉**的浏览方式。
>
> **状态：已落地到主站 `#/tree`。** 主站 52 项功能检查 + 14 项布局检查全绿；原型保留为参考实现（44 项）。
> 落地日期 2026-11-12。实现说明见 §8，与原方案的差异见 §9。

---

## 一、Ishkur 到底做对了什么

我把它站点的资源拆开看了（`layers.js` / `main.js` / `css.css`），它不是靠美术好看取胜，而是靠四个具体机制：

| 机制 | 实现方式 | 解决的问题 |
|---|---|---|
| **空间记忆** | OpenLayers 画布，全屏可平移缩放，每个风格固定在坐标上 | 位置本身就是记忆线索，第二次来找得回去 |
| **层级渐显** | 三层矢量图层按分辨率切换（`maxResolution` 16 / 40） | 缩远看骨架，拉近看细节，同一张图两种用途 |
| **节点即播放** | 点节点直接出声，底部拉出 50% 高的内容面板 | 「读到名字」和「听到声音」之间零跳转 |
| **荧光黄选中** | `#feff9d` 单色高亮 | 在满屏彩色块里唯一能一眼定位的锚点 |

它的**代价**也很明确，正好是我们不该抄的地方：

- **没有搜索**。1376 个条目在自由画布上找一条，只能靠拖。
- **没有面包屑**。缩放平移之后「我在哪、从哪来的」全靠自己记。
- **移动端锁死缩放**（`user-scalable=no`），小屏基本不可用。
- 作者自己在 FAQ 里承认：颜色无意义、连线不准确，为了可读性牺牲了准确性。

**结论**：抄「看得见分叉 + 节点即播放」，不抄「自由画布」。

## 二、方案：列式分支树（Miller Columns）

用**固定的横向列**代替自由画布——每一列是一个层级，往右点就长出新的一列。

```
┌─ ROOT / 大族 ─┐┌─ L1 / 下级 ──┐┌─ L2 / 下级 ──┐┌── 详情 / 听感 ──┐
│ ▶ House    122││ ▶ Chicago  38││   Piano House ││  Chicago House  │
│ ▶ Techno    95││   UK House    ││   Acid House  ││  House · 120BPM  │
│ ▶ Trance    78││   Euro House  ││   Hip House   ││                 │
│   Ambient     ││   Italo House ││   Detroit H.  ││  ▶ 播放这一段    │
└───────────────┘└──────────────┘└───────────────┘└─────────────────┘
     30 行           38 行            4 行            听感卡
```

### 为什么是这个形状

| 保留 | 放弃 | 理由 |
|---|---|---|
| 分叉一眼可见 | 自由平移缩放 | 不会迷路，不需要"重置视图"按钮 |
| 节点内嵌播放 | 全屏地图 | 1376 条不需要画布，需要的是**定位** |
| 列即层级 | 连线/坐标 | 层级关系由列位置表达，比连线更准 |
| 选中态强高亮 | 多色分类 | 沿用现有大族色，但只做 3px 边条 |

**关键取舍**：Ishkur 用空间换"壮观"，我们用结构换"找得到"。1376 条目在自由画布上是灾难，在列式树里是可控的——因为每列最多 40 行（实测 Fusion 族最大 40 个直接下级）。

### 实测数据支撑

跑脚本统计了真实分类树：

```
最大层级深度: 5        （每层条目数 329 / 640 / 287 / 94 / 26）
单节点最大下级数: 40   （Fusion 族）
有下级的分支节点: 303 / 1376
纯叶子条目: 1073
被多父节点引用: 0      （是纯树，不是 DAG —— 列式树成立的前提）
```

深度 5 层、单列最多 40 行、纯树无环——这三个数字决定了列式方案可行。**如果数据是 DAG（一条风格属于多个父类），列式树就会重复显示，方案得换。**

## 三、视觉：延续 Club Rig，不引入新语言

原型直接复用了主站的设计令牌，实测核对通过：

```js
bodyBg     = rgb(6, 6, 7)      // --ink
bodyColor  = rgb(242, 237, 227) // --paper
--sodium   = #ffb000           // 选中 / 主操作
--laser    = #ff2e63           // 播放中
```

**颜色语义**（沿用主站约定，不新增）：

| 颜色 | 含义 | 用在哪 |
|---|---|---|
| 琥珀 `--sodium` | 当前位置 | 选中行左边条、面包屑、进度线 |
| 洋红 `--laser` | 正在播放 | 播放按钮填充、行进度条 |
| 大族色 | 归属 | 仅 3px 左边条 + 圆点，不铺面 |

**明确不做**：Ishkur 那种 `#feff9d` 荧光黄不引入——它和 `--sodium` 的语义冲突，两个黄色会互相削弱。

## 四、设计约定

这一节写的是方案期的设计意图；实际落地的文件与偏差见 §8、§9。

### 文件落点

| 文件 | 改动 |
|---|---|
| `data/tree.js`（新） | 构建期预计算：把 `kb.js` 的 `childIds` 拍平成列式索引，避免运行时递归 |
| `app.js` | 新增 `renderTree()` + 路由 `#/tree`；`#/atlas` 保留为检索视图 |
| `styles-tree.css`（新） | 约 260 行，全部走现有 CSS 变量 |
| `index.html` | 引入新 CSS；主导航「查」下增加入口 |

### 与现有页面的关系

```
#/atlas   检索视图 —— 已知关键词，找条目     （保留不动）
#/tree    分支视图 —— 不知道名字，顺着分叉走  （新增）
#/listen  听感视图 —— 按速度和律动找          （保留不动）
#/family/:id  大族详情页                      （保留不动）
```

三者是**同一个知识库的三种入口**，不是替代关系。`#/atlas` 的左侧树面板（`treeHTML()`）将来可以换成跳转到 `#/tree` 的入口，减少重复实现。

### 数据流

```
kb.js (childIds)  ──构建期──▶  data/tree.js (列索引 + 声音解析)
                                      │
audio.js (EMAudio) ─── 事件驱动 ──────┤
  getState() / onState()              │
                                      ▼
                          app.js renderTree() ──▶ DOM
```

**声音解析优先级**（已实测每条都能出声）：

```
1. LISTEN.entries[id].fp   → 92 条有专属配方（标「专属」）
2. LISTEN.families[famId].fp → 1266 条走同族回退
3. 都没有                    → 18 条（全在「待归档」族），按钮置灰
```

### 播放状态同步（原型踩过的坑）

**不要用 `requestAnimationFrame` 轮询音频状态**。原型第一版这么写，在后台标签页被节流，界面和声音脱节，测试直接挂掉 3 项。

正确做法：

```js
Audio.onState(syncFromEngine);   // 引擎推送：播放/停止/换曲立刻响应
// 进度条额外叠加 140ms 低频轮询补间
```

`audio.js` 的 `notify()` 在 7 处调用，事件链是完整的。

## 五、响应式

实测六档宽度（320 / 390 / 768 / 1024 / 1440 / 1920）零横向溢出。

| 断点 | 行为 |
|---|---|
| ≥1200px | 三列 + 右侧详情并排 |
| 768–1199px | 列横向滚动，详情折叠到下方 |
| <768px | 单列 `scroll-snap` 吸附滑动，详情变全屏抽屉 |

**移动端关键数字**（实测）：
- 播放按钮 32×32（≥24px 触控标准）
- 行高 40px
- 列吸附 `scroll-snap-type: x mandatory`

**踩坑**：播放按钮最初桌面端 22px、移动端 26px——逻辑反了。桌面用鼠标同样需要目标面积，已统一为 28px 基准 / 移动端 32px。

### 数据契约

`data/tree.js` 的节点结构与 `kb.js` **不同**，这是移植时最容易踩的坑：

| 字段 | 含义 | 注意 |
|---|---|---|
| `children` | 子节点数组 | **已经是完整 key**（`e:g-383`），不是裸 id，不需要再拼前缀 |
| `parent` | 父节点 key | 不叫 `parentKey` |
| `sound` | `{fp, bpm, scope}` 或 `null` | `scope` = `own` / `family` / `fallback` |
| `subtree` | 子树规模 | 构建期算好，渲染不再递归 |
| `search` | 规范化搜索串 | 与 `app.js` 的 `norm()` 用同一套规则 |
| `pathLabel` | 祖先名链 | 搜索结果里区分同名条目 |

### 声音解析（构建期固化）

```
1. LISTEN.entries[id].fp      → 92 条专属配方          scope: own
2. LISTEN.families[familyId]  → 1266 条同族回退        scope: fallback
3. 都没有                      → 19 个节点（18 条目 + 1 个待归档大族）→ null
```

回退按**大族**而不是最近的祖先：大族是唯一有编辑保证的声音单位，按祖先回退会出现「同族两个兄弟听起来完全不同」，反而误导。

最大深度 5 · 分组 3（正式大族 24 / 补充收纳桶 5 / 待归档 1）

## 九、与原方案的差异

落地时改了四处，都是实测发现问题后的调整：

| 原方案 | 实际做法 | 原因 |
|---|---|---|
| `data/tree.js` 只存列索引 | 还存了派生关系、例曲、搜索串 | 否则详情卡要回查 `kb.js`，等于把省下的开销又加回来 |
| 详情卡只显示听感 | 加了「例曲」与「FROM / DERIVED / RELATED」三块 | 用户要的「派生关系」原本没进方案，落地时补上（1208 条有源头，474 条有分支） |
| 未提体积 | 裁掉 `description`（占 24%） | 树页只读 `summary`，完整正文在条目页；省下 830 KB |
| 未提 SW | 升级 `VERSION` 并缓存新文件 | 否则老访客吃到旧缓存，树页直接白屏 |
| 未提底部播放条 | **不另造**，直接用主站 `#audioDock` | 主站 dock 是居中浮层（`bottom:16px`、`z-index:95`），再放一条全宽底栏会叠在一起 |

### 落地时踩的坑（都已修复，记录备查）

1. **字段名三连错**：`childIds` → `children`、`parentKey` → `parent`、`pathLabel` 不存在。这类错误不会报错，只会静默失效（比如 `Enter` 键永远无法下钻）。
2. **`Audio.onState` 没订阅**：主站只在 `initAudio` 里订阅了 `updateAudioUI`，树的 `treeSyncFromEngine` 从未被注册，导致播放停止后行高亮不消失。
3. **`demoId` 前缀判断失效**：主站所有合成试听都是 `fp:` 前缀，用前缀判断「是不是我播的」会让旧高亮永远擦不掉。改成记住节点的 `demoId` 再比对。
4. **搜索规范化不一致**：构建期用 `toLowerCase()`，运行期用 `norm()`（会去空格），多词搜索必然失败。两边统一。
5. **`sel` 参数格式**：测试传带前缀的 key，解析函数期望裸 id。改成两种都认——手改 hash 的人不该需要知道前缀规则。
